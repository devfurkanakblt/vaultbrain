# Phase 7.6 — opt-in, unlocked-session personal memory

## Global constraints

- Ship generic code and synthetic fixtures only. Never inspect or commit a user's transcripts, vault, credentials, home paths, MCP configuration, or account data. Setup is an explicit runtime operation, not something development runs against the user's machine.
- Windows local Codex only; capture starts at enrollment, never scans old conversation content. One selected vault, desktop open and unlocked. No passphrase or data key crosses into Codex or the Node adapter.
- Use real encrypted notes, stable IDs, revisions and wiki links under logical `Memory/`. Reuse managed ciphertext formats, grants and audit. No plaintext memory cache, raw conversation archive, new encryption format, or implicit vault migration.
- Pairing is an explicit desktop-owner action. DPAPI-protected current-user pairing material and pointer-only backlog; no credentials in Codex config. Named pipe rejects remote/cross-user access. Same-user malware is outside this isolation guarantee.
- Automatic commits require unambiguous, non-sensitive user evidence. Assistant inferences, conflicts and sensitive information require review. Secrets are excluded before model transmission. Pinned/manually changed notes are not overwritten.
- At-least-once hook delivery and idempotent commits; cursor advances only after durable completion. Locked/closed jobs wait as protected references, expire after seven days with visible counts. Never claim unsupported transcript/hook versions succeeded.
- Forgetting excludes active records and their old sources from future recall/compilation; retain an encrypted tombstone. It does not securely erase revisions, backups, or Codex's own history. Explicit desktop action is required to relearn a forgotten fact.
- Supported Codex runner uses saved login with ephemeral schema-constrained runs, isolated config, no tools/MCP/hooks/web/apps/subagents; model default gpt-5.6-luna, low effort, no silent model fallback. Stream prompts on stdin and scrub errors. One worker, 60-second coalescing, bounded inputs/outputs. Lock/exit cancels and rejects stale results.
- Restore/rekey compatibility must be tested where APIs exist; do not implement Phase 7.4 or mark missing integration complete. All new privileged boundaries verify the keyring fingerprint.
- Preserve user work. No push, publish, live setup, account mutation, or real model request during development without explicit authority. Test-first changes; focused tests then full quality gates. Final result must distinguish implemented, verified and blocked requirements.

## Architecture and interface contract

The Rust desktop owns the vault session and a Windows named-pipe broker. The existing desktop executable also supports `--memory-client` before launching Tauri: bounded JSON stdin/stdout, no visible window. This native client owns DPAPI access and pointer spooling, avoiding a second installed native binary. Node's memory CLI/MCP invokes this executable via a user-selected absolute path stored by explicit runtime setup outside the repository. The app owns a single worker and invokes a packaged Node worker entry with plaintext only through anonymous pipes; runtime installation records the absolute Node/worker paths, never in checked-in config.

Wire protocol v1: request `{version:1, method, params}`; response `{version:1, ok:true, result}` or `{version:1, ok:false, error:{code,message}}`. Errors are generic, without paths or user content. MCP public methods are `memory_bootstrap`, `memory_search`, `memory_read`, `memory_remember`, `memory_forget`, `memory_status`. Additional owner-only Tauri operations pair/disconnect, inspect/review candidates, pause/exclude sessions/projects, forget/relearn and configure worker. Public callers never choose the vault path, grant identity, or worker command.

`MemorySource`: `{sessionId,turnId,messageId,role:'user'|'assistant',timestamp,text}`. Text exists only in runtime memory. `MemoryCandidate`: `{kind:'preference'|'fact'|'project'|'decision'|'goal'|'task'|'person'|'concept',title,body,evidence:[{messageId,quote}],sourceKind:'user-stated'|'inference',sensitive:boolean,links:string[],targetId?:string,baseRevision?:number}`. Quote matches actual user source; classification is a gate, not trust in model assertions. `MemoryBatch`: `{version:1,summary:string,candidates:MemoryCandidate[]}`. IDs/provenance derive locally; model never invents trusted source IDs. Status includes state, enrolledAt, paused, queued, review, failed, expired, lastCaptureAt, model and compatibility reasons; locked status is count-only.

## Task 1: Portable capture and model adapter

Own `src/memory/` portable modules and `test/memory*.test.mjs` for this task only; do not modify desktop/Rust/CLI/package scripts yet.

Implement protocol types/validators, explicit bounds, generic safe errors, secret exclusion, and a versioned Codex transcript parser with synthetic JSONL fixtures. Parse only visible user/assistant messages newer than enrollment from recognized rollout records; exclude tools, reasoning, compaction summaries, subagents and worker sessions. Unknown versions/records that affect message interpretation must report unsupported rather than fabricate data. File reads reject symlinks/reparse ancestry, enforce approved transcript roots/session identity and byte limits. Hook payload parser validates event/session/turn/source reference, never accepts a shell command. Persistent hook payload contains references and time only, not text/title/cwd where not necessary.

Implement candidate validation: exact real user quotes, bounded strings/counts, no secrets, finite enums, namespace-safe links, unresolved targets preserved for review. Return auto/review/rejected classification; do not mutate notes. Derive stable per-source dedupe keys independent of hook event and summarizer version. Bootstrap renders untrusted factual context bounded conservatively to <=1500 tokens (a UTF-8-byte upper bound is acceptable and safe), with source references; no truncated JSON or file spill.

Implement an isolated Codex subprocess runner and `src/memory/worker.ts` executable. Its JSON input contains normalized messages and bounded existing-memory context, not credentials or arbitrary config/commands. It returns validated batch JSON only. Use stdin, ephemeral sessions, schema file containing no user data, strict configuration, disabled tools/features and zero inherited provider overrides/secrets. Enforce timeout/output limits, abort handling, no shell, windowsHide, redacted stderr, no retry storm or model fallback. Only support tested adapter versions (initial local CLI 0.153.1); incompatible flags/config fail closed. Tests use a synthetic child executable at the subprocess boundary, not a paid account or mock-only assertions. Provide command/config construction tests as behavior, cancellation/overflow tests, quote/secret/transcript tests. Package runtime entry must be import-safe in tests.

Report public exports and test commands. Do not invent full compatibility from mocks: native live validation belongs to acceptance.

## Task 2: Native unlocked-session broker and durable memory service

Own `src-tauri/src/memory/`, minimal lib.rs/main.rs/keyring.rs/Cargo.toml/build.rs/capability integration, Rust tests and shared synthetic format fixtures. Consume Task 1 wire/model schema. No desktop React or TypeScript CLI edits.

Implement session-bound native memory service. Use existing document CRUD/history/journals, shared vault lock, refreshed index and UI change event. Retain kv/audit keys in Zeroizing memory only for the unlocked session (legacy memory enrollment must refuse and request explicit migration). Capture keyring content fingerprint at session open and verify at every broker boundary and privileged desktop boundary; active v2 retiring keys refuse memory access. Existing ordinary document behavior stays compatible.

Persist memory-control state in `memory-system.kv.enc` under existing keyed KV encryption/AAD, grants in existing grants.enc. Read/check existing grant semantics natively including expiration/revocation/redaction/confirmation; memory never bypasses restrictive grants or exposes control state. Pairing creates a random identity with a memory-only grant, client credentials stay DPAPI outside vault. Authenticate current-user-only local named pipe and its server identity; reject remote, fake server, oversized/truncated frames, unknown methods. Client can only submit references/candidates and read authorized memory, never issue arbitrary filesystem commands. Support explicit owner pairing confirmation, disconnect/rotation, and `--memory-client` modes for request/hook/status/doctor/configuration coordination. No GUI window for client mode. Non-Windows reports unsupported without unsafe fallback.

Audit using current TS canonical ordering/HMAC and signed-head format, under the shared lock. Add cross-core vectors. Use pending/terminal IDs for mutations and reconciliation; never leak note text/title/source paths. No audit write using stale keys or while locked.

Single durable queue dedupes sources, keeps cursor after commit, recovers crashes. While locked only DPAPI/ACL-protected pointer records (7 day TTL, bounded backlog and visible expired/failed counts), process only after selected vault unlock. Enrollment cutoff forbids history import; validate source references and reject symlinks. Invoke Node worker via owner-approved runtime paths/arguments, anonymous stdin/stdout, no shell. Coalesce 60 seconds, one child, cancel and discard results on lock/session generation changes. Avoid holding session/vault locks over model execution. Quota/network errors back off; incompatible adapters stop. Source text never persisted outside existing Codex transcript.

Commit auto-safe candidates as Memory notes with provenance and daily-summary wiki links. Review others. Enforce UUID registry membership, not path-prefix alone. Respect pinned/manual revisions and conflicts. Reads search only active allowed memory; return bounded bootstrap/read/search payloads with redaction. Forget is an owner-approved durable operation: remove active retrieval, invalidate affected summaries/queued sources, keep tombstones; no automatic resurrection or physical-erasure claim. Pausing and exclusions cancel pending jobs. Expose owner Tauri commands and publish their exact DTOs for Task 3.

Test native service with temporary synthetic vaults, cross-user/pipe/DPAPI Windows tests, lock/abort/cursor/failure injection, grant boundaries, manual revisions, graph/index live changes, audit parity, wrong-key/fingerprint changes, recovery vectors and missing full-rekey integration as an explicit gap. Never touch real vaults/config/transcripts.
